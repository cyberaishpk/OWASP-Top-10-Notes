# CWE-284: Improper Access Control

## Definition
Improper Access Control happens when an application doesn't correctly check whether someone is allowed to access a resource, page, or piece of data. If those checks are missing or broken, people can reach things they shouldn't be able to reach.

## Why it's the parent category
CWE-284 is what MITRE calls a **"Pillar"** — the most general, top-level weakness in the access control family. Access control involves several protection mechanisms: **authentication** (proving who you are), **authorization** (making sure you can access a resource), and **accountability** (tracking what actions were performed). When any of these fails, attackers can gain privileges, read sensitive data, execute commands, or evade detection.

Because it's so broad, MITRE actually recommends **not** mapping real CVEs directly to CWE-284 — instead you use one of its more specific children:

- CWE-862 – Missing Authorization
- CWE-863 – Incorrect Authorization
- CWE-306 – Missing Authentication
- CWE-732 – Incorrect Permission Assignment
- CWE-639 – Authorization Bypass Through User-Controlled Key (IDOR)

So think of CWE-284 as the "family name," and the CVEs/vulnerabilities you'll actually study fall under its children.

## Root causes
There are two distinct ways this weakness gets introduced: **Specification** and **Enforcement**.

- **Specification problem** — permissions are set wrong to begin with (e.g. a password file made world-writable, or a guest account given admin rights).
- **Enforcement problem** — the access control mechanism itself has a bug, so even correct rules aren't actually enforced (e.g. a broken ACL check, or letting a user set their own privilege level).

## Real-world example
A well-known case is **CVE-2021-21972**, affecting VMware vCenter Server. A cloud computing virtualization platform did not require authentication for uploading a file, then used ".." path traversal sequences in that file to reach unexpected files — and this was actively exploited in the wild, per CISA's Known Exploited Vulnerabilities catalog. In short: no access control on a file upload endpoint let attackers walk outside the intended folder and eventually gain remote code execution on the server.

## How to test for it (pentester mindset)
- Try reaching admin or restricted pages while logged in as a normal/low-privilege user
- Change IDs or parameters in requests to target another user's data
- Test whether authorization is enforced on the server, not just hidden in the UI
- Check for missing checks on *every* endpoint, not just the main ones (attackers often find the one form or API route that was forgotten)
